1. ADMIN AVAILABILITY CHECK (HIGHEST PRIORITY - CHECKED FIRST)
   Status: ✅ IMPLEMENTED
   
   WHERE IT HAPPENS:
   File: backend/src/appointments/appointments.service.ts (Lines 120-131)
   
   WHAT IT DOES:
   - Extracts adminId from JWT token (never from user input)
   - Queries database for existing appointments with same admin + date + time
   - SQL: SELECT * FROM appointments 
          WHERE admin_id = :adminId 
          AND DATE(date) = :date 
          AND time = :time 
          AND status = 'scheduled'
   
   RESULT IF FOUND:
   - Returns error: "You already have an appointment booked for this date and 
                     time slot. Each admin can only have one appointment per 
                     time slot."
   - Booking BLOCKED - staff check is skipped


2. STAFF AVAILABILITY CHECK (CHECKED SECOND)
   Status: ✅ IMPLEMENTED
   
   WHERE IT HAPPENS:
   File: backend/src/appointments/appointments.service.ts (Lines 138-178)
   
   WHAT IT DOES:
   - Gets list of active staff members for tenant
   - Checks for time conflicts between new appointment and existing ones
   - Considers appointment duration to detect overlaps
   - Filters available staff (those with no conflicts)
   
   RESULT IF NO STAFF AVAILABLE:
   - Returns error: "No staff available for the selected time slot"
   - Booking BLOCKED


3. AUTO-ASSIGN FIRST AVAILABLE STAFF
   Status: ✅ IMPLEMENTED
   
   WHERE IT HAPPENS:
   File: backend/src/appointments/appointments.service.ts (Lines 176-186)
   
   WHAT IT DOES:
   - Selects first available staff from filtered list
   - Sets staffId automatically (admin cannot influence this)
   - Creates appointment with both adminId and staffId

================================================================================
WORKFLOW - STEP BY STEP
================================================================================

STEP 1: Admin Clicks Calendar Slot (e.g., Monday 10:00 AM)
        ↓
STEP 2: Admin enters title, duration, type, notes in booking form
        ↓
STEP 3: Frontend sends request: POST /appointments with form data
        ↓
STEP 4: Backend STEP 1 - Check Admin Availability
        - Query: admin_id = X AND date = Monday AND time = 10:00
        - If found: ❌ BLOCK (admin already has appointment)
        - If not found: ✅ PROCEED to STEP 2
        ↓
STEP 5: Backend STEP 2 - Check Staff Availability
        - Get active staff for tenant
        - Filter by time conflicts
        - If available staff found: ✅ PROCEED to STEP 3
        - If no staff: ❌ BLOCK (no one available)
        ↓
STEP 6: Backend STEP 3 - Create Appointment
        - Auto-assign first available staff
        - Save: adminId (from JWT), staffId (auto-assigned), date, time, etc.
        - Return appointment with staffId and staff details
        ↓
STEP 7: Frontend displays success message
        - "Appointment booked successfully! Staff will be automatically assigned."
        - Shows assigned staff name
        ↓
STEP 8: Calendar refreshes
        - Shows admin's appointment
        - Other admins see same slot available (different staff)


================================================================================
MULTI-ADMIN SCENARIO - HOW IT WORKS
================================================================================

SCENARIO: 3 admins, same time slot (10:00), 3 staff available

Timeline:
1. Admin A books 10:00 → Gets Staff S1
2. Admin B books 10:00 → STEP 1: ✅ (different admin), STEP 2: ✅ S2 available, Gets Staff S2
3. Admin C books 10:00 → STEP 1: ✅ (different admin), STEP 2: ✅ S3 available, Gets Staff S3
4. Admin D books 10:00 → STEP 1: ✅ (different admin), STEP 2: ❌ No staff left, BLOCKED

DATABASE STATE:
admin_id    | staff_id  | date       | time
============|===========|============|==========
Admin-A     | Staff-S1  | 2025-01-20 | 10:00
Admin-B     | Staff-S2  | 2025-01-20 | 10:00
Admin-C     | Staff-S3  | 2025-01-20 | 10:00


SAME ADMIN DOUBLE-BOOK ATTEMPT:

Admin A tries to book 10:00 again → STEP 1: ❌ FOUND existing appointment, BLOCKED

Result: Admin A cannot double-book at same (date + time)


================================================================================
KEY BUSINESS RULE ENFORCEMENT
================================================================================

✅ ADMIN CHECK HAPPENS FIRST
   - Before any staff availability check
   - Prevents admin from having 2+ appointments at same time

✅ ADMIN CANNOT DOUBLE-BOOK
   - Query: WHERE admin_id = X AND DATE(date) = Y AND time = Z AND status = scheduled
   - Single admin limited to ONE appointment per date + time slot

✅ DIFFERENT ADMINS CAN BOOK SAME SLOT
   - Each admin is independent
   - Limited by available staff
   - If 3 staff available, 3 admins can book same time (different staff each)

✅ AUTO-ASSIGN PREVENTS BYPASS
   - Frontend never sends staffId
   - Backend always auto-assigns
   - Admin cannot select staff manually

✅ JWT TOKEN REQUIRED
   - adminId from @CurrentUser() decorator (JWT token)
   - Never extracted from request body
   - Impossible for frontend to manipulate
